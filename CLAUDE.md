# Renumber

Плагин Revit: нумерует экземпляры семейств категории в текстовый параметр —
`F-01`, `F-02`, … По умолчанию Mechanical Equipment → Mark, но категория,
семейства и параметр выбираются.
Автор: Yoav (HVAC-инженер, T.E.S / Vixeldorf). Рабочий язык обсуждений — русский,
код, комментарии и коммиты — английский.

## Как устроено

```
App                      лента: вкладка Vixeldorf → панель Renumber, Help Center, проверка обновлений
RenumberCommand          открывает окно (модальное — API-контекст жив, окно пишет само)
   │
RenumberWindow (WPF)     слева настройки, справа живое превью, одна кнопка записи
   │
   ├─ ModelQuery         категории с экземплярами, семейства, текстовые параметры экземпляров
   ├─ ScopeSource        документ + активный вид + выделение на момент запуска
   ├─ RenumberPlanner    план: старое → новое значение для каждого элемента, ничего не пишет
   │    ├─ NumberFormat      префикс + число с нулями + суффикс; чтение номера обратно
   │    ├─ NumberPattern     распознаёт форматы в значениях: F02, F03 → «F##» (префикс F, 2 знака)
   │    └─ NumberAllocator   раздаёт номера по сетке start + k·step, пропуская занятые
   ├─ RenumberWriter     одна транзакция = один Undo
   ├─ SettingsStore      последнее правило в %AppData%\Vixeldorf\Renumber\settings.json
   └─ UpdateChecker      version.json с GitHub (ioavant/Renumber, master) → баннер в окне
```

`NumberFormat`, `NumberAllocator` и `NumberPattern` не зависят от Revit — их можно гонять в
консоли (так и проверено: тест в scratchpad, линкует оба файла, net8).

## Правила нумерации

- **Формат задаётся примером.** Старт `01` → два знака (`F-01 … F-99, F-100`),
  старт `1` → без нулей. Шаг ≥ 1. Суффикс необязателен.
- **Чтение номера** — без учёта регистра и нулей: `F-7`, `f-07`, `F-07` — это 7.
  Для дубля Revit и для человека на чертеже это одна марка.
- **Занятые номера считаются по всей категории**, а не только по выбранным
  семействам: Revit проверяет Mark на дубли в пределах категории.
- **Дубль**: при повторе номера его сохраняет самый старый элемент (меньший Id).
- **Режимы**:
  - `Renumber all` — все элементы в охвате получают номера с начала, по порядку.
    Если новый номер совпадает с номером элемента вне охвата / невыбранного
    семейства — строка помечается оранжевым (конфликт), но пишется.
  - `Only empty — continue after the last` — только пустые; продолжают после
    максимального номера ≥ старта. Номера ниже старта не двигают точку отсчёта.
  - `Only empty — fill gaps first` — только пустые; сначала занимают дыры.
  - Галка «дубли как пустые» (в режимах only empty): копия элемента с тем же
    номером получает новый.
  - `Change format — keep the numbers` (`Reformat`): значения в старом формате
    (Old prefix / Old suffix) получают тот же номер в новом: `F02` → `F-02`.
    Новые префикс/суффикс — из основных полей, Start задаёт только число знаков,
    Step не используется. Пустые и чужие значения не трогаются; дубли остаются
    дублями (помечаются оранжевым). Аллокатор в этом режиме не участвует.
- **Распознавание формата** (`NumberPattern`): число — последняя группа цифр
  (`AHU-1-03` → префикс `AHU-1-`, 3), префикс/суффикс без учёта регистра,
  ширина — минимальная длина цифр в группе. Под примером формата — ссылки
  «In use: F## ×3 · AHU-# ×1» по элементам в охвате: клик в режиме
  Change format заполняет старый формат, в остальных — новый (префикс, суффикс,
  Start с нужными нулями). При переключении в Change format пустой старый
  формат заполняется самым частым.
- **Значения в чужом формате** (`AHU-1`) в режимах only empty не трогаются.
- **Порядок**: по Id (порядок создания), по текущему номеру (закрыть дыры без
  перестановки), по уровню → рядами / колонками (допуск ряда 1 м).
- **Пропускаются**: нет параметра, read-only, элемент занят другим пользователем
  (workshared). Вложенные shared-компоненты (`SuperComponent != null`) в
  нумерацию не входят — они принадлежат хосту.
- **Охват**: весь проект / видимые в активном виде / текущее выделение. Если при
  запуске что-то выделено — по умолчанию выделение.

## Сборка и тест

Две сборки, как в остальных плагинах (скилл `revit-net8-split`):

```
Revit     Framework         Компилируется против    Выход
2024      net48             установленный 2024      bin\<Config>\Vixeldorf\
2025+     net8.0-windows    2025.0 из NuGet         bin\<Config>\Vixeldorf\net8\
```

Бренд — через общий движок `..\_branding` (только Vixeldorf; GUID в
`branding.props`, UpgradeCode/AddInId не менять). `Renumber\Directory.Build.props`
импортирует корневой вручную — MSBuild берёт только ближайший.
Версия — только в `version.json` (из него VersionInfo.cs, а MSI берёт версию из DLL).

```
.\build.ps1                                   # Release + MSI
.\build.ps1 -Configuration Debug -NoInstaller
```

MSI: `Installer\bin\Release\Vixeldorf\Renumber_Setup.msi` (имя файла завязано
на downloadUrl в version.json). Релиз: поднять версию в `version.json` (и
downloadUrl), собрать, `gh release create vX.Y.Z` с MSI, запушить version.json
в master — по нему установленные копии видят обновление.

Проверка ссылок — **в отдельном процессе на каждый DLL**:
```
net48:  mscorlib 4.0,       RevitAPI 24.3,  Newtonsoft.Json 13.0
net8:   System.Runtime 8.0, RevitAPI 25.0,  PresentationFramework 8.0
```

Тест — Revit 2024 через Add-in Manager (грузит DLL напрямую, .addin не нужен):
`Renumber\bin\Debug\Vixeldorf\Renumber.dll` → `Renumber.Commands.RenumberCommand`.

## Дальше: фоновый режим (IUpdater)

Цель: плагин сам следит за новыми элементами заданной категории/семейств и сразу
ставит им номер. По умолчанию — **продолжать после последнего** (`ContinueAfterLast`),
опционально — занимать освободившиеся номера (`FillGaps`). Пример: удалили F-23,
создали новый элемент → по умолчанию он получает F-(max+1), в режиме gaps — F-23.

Задел уже есть: `NumberingRule` — чистый DTO, `NumberAllocator` берёт набор
занятых номеров и режим, `RenumberPlanner` уже умеет «только пустые + дубли».

План:
1. Правило хранить **в модели** (Extensible Storage на ProjectInfo или
   DataStorage), а не в %AppData%: в workshared-файле все пользователи должны
   нумеровать одинаково, и правило должно ехать вместе с файлом.
2. `IExternalApplication` (App.cs, ribbon по скиллу `vixeldorf-ribbon`):
   регистрирует `IUpdater` на `Element.GetChangeTypeElementAddition()` с фильтром
   `ElementCategoryFilter` + `ElementClassFilter(FamilyInstance)`. Плюс
   включатель «Auto-numbering on/off» на ленте.
3. В `IUpdater.Execute` транзакция уже открыта — писать напрямую, без своей.
   Занятые = все номера категории, кроме добавленных; добавленные без номера
   или с дублем (копия!) → `NumberAllocator.Next()`.
4. Подводные камни, которые надо проверить:
   - Копирование/вставка и Ctrl+C массивом — одно событие на пачку, порядок по Id.
   - Revit сам инкрементирует Mark при копировании у части категорий — учесть,
     иначе получим двойную нумерацию.
   - Undo откатывает и изменение апдейтера — это нормально.
   - Workshared: апдейтер не должен падать на чужих элементах; при открытии
     модели без плагина Revit спросит про отсутствующий updater — пометить
     `SetUpdaterOptional(true)`.
   - Удаление элемента апдейтер не трогает: дыры заполняются только при
     следующем добавлении (режим gaps) или кнопкой Renumber.
